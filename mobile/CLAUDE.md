## What you are working on

A separate Expo client at `plnt-cloud/mobile/` that talks to the SAME
FastAPI + Temporal surface the web app uses. You are **not** migrating
Atlas; you are building a parallel consumer client.

Stack — do not deviate without flagging in chat:
- Expo SDK 54, expo-router 6, React Native 0.81, new arch on
- NativeWind 4.x (token-bridge with `web/src/styles/tokens.css`)
- `@tanstack/react-query` 5
- `react-native-maps` (Google Maps native)
- `@gorhom/bottom-sheet`, `@shopify/flash-list`, `react-native-reanimated` 3
- `expo-image`, `expo-location`, `expo-notifications`
- `zustand` (cart only), `react-hook-form` + `zod`
- `openapi-typescript` (generate from FastAPI's `/openapi.json`)

## Hard rules — broke any of these before

1. `babel.config.js`: `babel-preset-expo` with `jsxImportSource:'nativewind'`
   MUST be the first preset entry, then `'nativewind/babel'`. Swapping
   order breaks Metro silently (no className styling).
2. If you add `supabase` or any other fetch-from-browser library, import
   `react-native-url-polyfill/auto` AT THE TOP of the client module or
   `fetch()` silently fails on RN.
3. `eas.json` `base.android.env.GRADLE_OPTS` bumps gradle memory. Don't
   shrink. Android dev builds run 60-75min.
4. Any `app.json` edit → `npx expo prebuild --platform <p> --clean`. No
   exceptions. Run `npm run prebuild:ios` / `npm run prebuild:android`.
5. `app.json` `updates.requestHeaders.expo-channel-name` MUST be set or
   OTA checks resolve to nothing (HDGEcalls v0.3.2 incident).
6. No `.env` in repo — use EAS secrets for builds, copy
   `.env.development.example` → `.env.development` locally (gitignored).
7. No raw `fetch` from components. Every API call goes through a typed
   wrapper in `src/lib/api/` with shape validation (zod). Mirror the
   HDGEcalls `isMeResponse` pattern.
8. Jest harness from day 1 for slot/availability/conflict logic. See
   `__tests__/`.

## Backend reach

The FastAPI surface lives on the dev machine, exposed via a Cloudflare
named tunnel. Read `mobile/.env.development` for `EXPO_PUBLIC_API_BASE`
and `EXPO_PUBLIC_WS_BASE`. **Do not hardcode URLs.** If the tunnel
isn't up, you'll see `ECONNREFUSED` — stop and flag in chat. Don't add
a fake/mock mode for "tunnel down".

The CORS allowlist on the API needs to include your cloudflared hostname
— see `plnt-cloud/.env`'s `CORS_ORIGINS`.

## WS envelope — must match web Atlas exactly

`features/chat/ChatPanel` (web) prefixes EVERY user message:

    [biz:<place_id> agent:<slug>] <user text>

When `userLoc` is set, geolocation is appended after:

    [biz:<place_id> agent:<slug>] <user text> [@<lat>,<lng>]

When no business is scoped (Home freeform search routed to
`classify_intent`), the envelope drops the `[biz:… agent:…]` prefix and
sends raw text (still with `[@lat,lng]` if available). This matches
`Atlas.onSendRaw`.

Mobile MUST send the same envelope so the backend doesn't fork.

## Action cards — driven by `action.kind`, never as chat text

The synthesizer's `say` replies may carry an `action` payload:
- `offer_slots` → render slot chips inline; tap → confirm-book
- `booking_confirmed` → success card with `booking_id`
- `booking_failed` → reason card

These NEVER render as chat bubbles. One agent voice in chat — same
contract as web Atlas. See `src/features/chat/useWsChat.ts` (port of
`web/src/features/chat/useWsChat.ts`).

## Tokens are bridged, not hand-written

`src/styles/tokens.js` is GENERATED by `node scripts/sync-tokens.mjs`
from `plnt-cloud/web/src/styles/tokens.css`. Don't hand-edit it.
`tailwind.config.js` reads it. After upstream token changes:

    npm run tokens:sync

## Shared seed — no duplication

The map seed (`SAMPLE_BUSINESSES`), `Business`/`Vertical` types, the
vertical metadata, and the agent registry live in `plnt-cloud/web/src/
features/`. Mobile imports them via the `@web/*` tsconfig path, which
Metro resolves via `watchFolders` in `metro.config.js`. There is no
copy on the mobile side — edits to those files in `web/` reach mobile
on the next bundler restart.

## Identity

Anonymous user. `src/lib/storage/identity.ts` stores a per-install
`user_id` in `AsyncStorage` (key `plnt.user_id`). Matches web Atlas's
pattern of an opaque anon id; no Supabase Auth, no signup, no login
screens until product asks for one. Don't add them.

## Iteration loop

```bash
cd plnt-cloud/mobile

cp .env.development.example .env.development   # first time
npm install                                    # first time
npm run tokens:sync                            # re-run after web tokens change
npm run openapi:sync                           # re-run when FastAPI schema changes

npx expo start --dev-client                    # dev (needs a dev-client build)

# Dev-client builds (first time, or after native code / config changes)
eas build --profile development --platform ios
eas build --profile development --platform android
```

If you change `app.json` or add a native module: `npm run prebuild:ios`
or `npm run prebuild:android`, then rebuild the dev client. No
exceptions.

## Things that look like bugs but aren't

- **`className` on `<View>` has no effect** → babel preset order. See
  rule #1 above.
- **WS connection works in the browser but ECONNREFUSED on device** →
  device can't reach `localhost`. Mobile must hit the cloudflared
  hostname even in dev; that's what `.env.development` is for.
- **Map renders blank on iOS Simulator** → `googleMapsApiKey` is the
  placeholder. Replace in `app.json` and re-prebuild.
- **`@web/*` import resolves in TS but Metro can't find it** → you
  added a path to `tsconfig.json` but didn't extend `watchFolders` in
  `metro.config.js`. Both must agree.
- **Reanimated worklets throw `_WORKLET is undefined`** → the plugin
  isn't last in `babel.config.js` plugins. Move it to the bottom.
